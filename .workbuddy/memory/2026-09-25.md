## 任务二：功能装配台（解决「提示词只有框架、没有功能」）

### 问题定性
用户反馈：生成的提示词只有框架，没有功能，且用户无法写入自己的功能。
根因：提示词第 3 节直接输出 `a.modules`（原型里的 6–9 行模块名，如"商品发布"），**无业务规则、无字段、无接口**；数据模型/接口/页面也只来自原型自带列表，与用户需求脱节。

### 改造方案
1. **新增 `FEATURES` 功能库（50 条）**，每条含 `desc / rules / ent / apis / pages / tier / cat / arch`：
   - `rules` 业务规则共 196 条（写的是并发、幂等、越权、超卖等"同行真正会做错"的硬约束）
   - `ent` 53 条、`apis` 133 条；分类 8 组；优先级 P0=23 / P1=21 / P2=6
   - `arch:["*"]` 表示通用；其余绑定原型 id
2. **`applyArchetype` 增加 `changed` 守卫**：只有原型真的换了才重置功能清单，否则保留用户裁剪 —— 修掉了"裁剪后被推荐列表灌回"的缺陷
3. **合并式生成**：`mergedEntities()` 原型+功能按实体名去重、字段取并集；`mergedApis()` 功能接口优先去重；`mergedPages()` 同理。实测电商项目从 6 实体 → 39 实体、98 接口
4. **提示词第 3 节改为「功能规格」**：逐条输出 说明 / 业务规则 / 涉及实体 / 相关接口 / 相关页面，并带 ［P0 必须］等标记；验收标准新增"第 3 节 N 项功能全部实现"与"业务规则都要能找到实现"
5. **界面**：hero 与链路图之间插「② 功能清单」区块；功能卡（分类筛选 / 关键词搜索 / 点击勾选）；「选中全部推荐 / 只留必须项 / 清空」；**自定义功能输入框一行一条、边写边生效**（不用点按钮），自定义项以橙色虚线标签置顶；底部汇总条 + 「按这份清单重新生成」
6. **提速**：想法输入 420ms 防抖自动识别原型并刷新推荐；`Ctrl/Cmd+Enter` 全局快捷生成；输出栏显示 `N 项功能 · 提示词 X k 字符`
7. **修掉发送截断**：`btnSendOut` 原先把提示词 `slice(0,4000)`，而功能规格在后半段，等于丢掉了最有价值的部分 → 改为原样送全量
8. **清理死数据**：ARCHETYPES 的 8 处 `modules:[...]` 已无任何代码引用，删除

### 规模

- 实测：电商全量 41 项功能（39 库内 + 2 自定义）/ 39 实体 / 98 接口 / 提示词 25.5k 字符；只留 P0 约 6.3k 字符

### 踩坑（本轮新增，务必记住）
1. **jsdom 里 `const` 声明不挂到 `window`**，只有**函数声明**会。取 `FEATURES`/`state`/`OUT_EXT` 这类 const 必须走 `w.eval("FEATURES")`。用 `w.FEATURES` 会得到 undefined，看起来像产品坏了，实际是测试写法错。（`pickedList`/`renderFeatures` 是函数声明，`w.` 能直接取到——这个差异极具迷惑性）
2. **`getBoundingClientRect()` 审计触摸目标会漏报**：用伪元素扩展的命中区量不到；且**伪元素被祖先 `overflow:hidden` 裁掉时，扩展方案本身失效**（功能卡 `overflow:hidden` 裁掉了 `::before`）→ 改用真实高度 + 负外边距。审计侧用 `elementFromPoint` 上下探测计算"有效命中高度"
3. **断言失败先证伪断言**：本轮 `套用预设后被还原 3 项` FAIL（实际 2 项），查明是测试跑到该步时 `archId` 仍为 `default`，而测试选的两项只适用 commerce/saas/admin——**过滤是正确设计**，是断言选错了样本
4. 用 `cp` 备份后再改主文件（本轮备份到 `.workbuddy/_bak_before_upgrade.html`）
