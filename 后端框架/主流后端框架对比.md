# 主流后端框架对比与选型决策

## 一、五种语言的定位

| 语言 | 优势 | 代价 | 典型场景 |
|---|---|---|---|
| TypeScript (Node) | 前后端同语言，共享类型，生态最大 | CPU 密集任务弱 | 全栈单体、BFF、API 网关 |
| Python | AI / 数据生态最强，语法简洁 | 性能一般，需异步框架 | AI 服务、数据接口、爬虫 |
| Java | 企业级稳、强类型、生态最重 | 启动慢、内存开销大、样板多 | 大型企业系统、金融 |
| Go | 并发原生、单二进制、部署极简 | 泛型与错误处理体验一般 | 高并发 API、云原生 |
| Rust | 内存安全 + 极致性能 | 学习曲线最陡、开发速度慢 | 基础设施、性能敏感服务 |

## 二、框架横向对比

| 框架 | 语言 | 定位 | 什么时候选 | 什么时候别选 |
|---|---|---|---|---|
| **NestJS** | TS | 企业级、依赖注入、模块化 | 团队协作、需要清晰分层 | 只写 3 个接口的小脚本 |
| **Express** | TS | 极简、中间件生态最全 | 快速原型、小型 API | 大型项目（缺乏约束） |
| **Fastify** | TS | 高性能 Express 替代 | 需要吞吐量与 schema 校验 | 生态插件不如 Express 全 |
| **Hono** | TS | 超轻量、边缘计算友好 | Cloudflare Workers / Deno / Bun | 需要重型 ORM 与复杂中间件 |
| **FastAPI** | Python | 异步 + Pydantic + 自动 OpenAPI | AI 服务、数据接口、快速交付 | 需要极强 ORM 关系建模时的复杂场景 |
| **Django** | Python | 全家桶、自带 Admin | 需要现成后台与 ORM 的中型项目 | 想保持轻量、只做 API |
| **Spring Boot** | Java | 全家桶、约定大于配置 | 企业 Java 标准、大团队 | 个人小项目（过重） |
| **Quarkus / Micronaut** | Java | 启动快、内存低、GraalVM | Serverless、容器密度敏感 | 生态成熟度要求极高 |
| **Gin** | Go | 主流、极简高性能 | Go Web API 默认选择 | 需要强约束的大型工程 |
| **Echo / Chi / Fiber** | Go | 均衡 / 轻路由 / fasthttp 极速 | 按口味与性能需求替换 Gin | — |
| **Hertz** | Go | 字节开源，高性能 | 国内大厂技术栈 | 社区资料相对少 |
| **Actix-Web** | Rust | 性能顶尖 | 极致性能要求 | 团队不熟 Rust |
| **Axum** | Rust | Tokio 官方，组合式 | 生态与官方支持好 | — |

## 三、决策表（按你的实际情况选）

| 你的情况 | 推荐 | 理由 |
|---|---|---|
| 一人全栈，已会 JS | NestJS 或 Express | 与前端同语言，心智负担最低 |
| 学校课程 / 目标进大厂 | Spring Boot | 招聘与课程覆盖最广 |
| 做 AI 应用 | FastAPI | Pydantic 校验 + 自动文档 + 异步 |
| 高并发 / 云原生 | Gin | 并发模型简单、单二进制、容器友好 |
| 边缘计算 | Hono | 多运行时兼容，冷启动极小 |
| 已有 Java 团队 | Spring Boot | 不折腾，生态最稳 |
| 性能极致且团队懂 Rust | Axum / Actix-Web | 无 GC、内存安全 |

## 四、API 协议怎么配套

| 协议 | 适用 | 注意 |
|---|---|---|
| REST | 90% 项目 | 统一响应结构、版本前缀 `/api/v1` |
| GraphQL | 前端按需组合字段、多端消费 | 防 N+1、限制查询深度 |
| gRPC | 服务间通信、多语言 | 需要 Protobuf 工具链 |
| tRPC | 前后端同 TS | 只适合 TS 单体或同仓 |

---

## 五、跨语言都适用的四条纪律

1. **统一响应结构** `{ code, message, data }`，HTTP 状态码与业务码分离
2. **统一错误处理中间件**，禁止把堆栈直接返回给前端
3. **配置全部走环境变量**，`.env.example` 进版本库、`.env` 进 .gitignore
4. **连接池必备**，禁止每请求新建数据库连接

## 六、学习路径建议（以 TS 为例）

```
Express 基础（1 周）
  → 理解中间件、路由、错误处理
NestJS（2–3 周）
  → Module / Controller / Service 分层
  → 依赖注入、Guard、Interceptor、Pipe
  → Prisma 接入 + 全局异常过滤器
工程化
  → DTO + class-validator 校验
  → 日志（pino / winston）
  → 测试（Jest + supertest）
```
