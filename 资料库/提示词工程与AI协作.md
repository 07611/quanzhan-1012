# 提示词工程：写给编程智能体的提示词

> 解决了「同一个模型，别人生成的能跑，我生成的是一堆假数据」的问题。

## 一、核心结论：结构 > 字数

大模型对**结构化、可验证**的指令响应最好。一份能产出可运行项目的提示词，通常包含以下七个部分。缺哪一块，模型就用它的默认值补齐——那通常不是你想要的。

| 序号 | 部分 | 作用 | 缺失后果 |
|---|---|---|---|
| 1 | 角色与交付纪律 | 限定身份与输出规范 | 输出占位符、省略代码 |
| 2 | 项目目标 | 说清是什么、给谁用 | 功能偏离预期 |
| 3 | 技术栈（锁定） | 约束框架与语言 | 自作主张换成它熟悉的栈 |
| 4 | 数据模型 | 实体 + 字段 + 关系 | 表结构混乱、字段随意 |
| 5 | 接口契约 | 方法 + 路径 + 用途 | 前后端对不上 |
| 6 | 页面与路由 | 页面清单与关键交互 | 只给一个页面 |
| 7 | 设计规范 | **具体色值与字号** | 生成默认 Bootstrap 风 |

## 二、七部分怎么写

### 1. 角色与交付纪律

```
你是一名资深全栈工程师。请严格依据本任务书，产出可直接运行、可部署的完整项目代码。
1. 先输出完整文件树，再逐个文件输出完整代码，标注每个文件的相对路径
2. 禁止假数据写死：前端必须真实调用后端接口，后端必须真实读写数据库
3. 所有密钥走环境变量，附 .env.example
4. 统一响应结构 { code, message, data }
5. 给出可直接执行的安装、启动、构建命令
```

> 「**禁止假数据写死**」这一条最关键。不写它，模型有相当概率给你返回一个写死数组的「演示版」。

### 2. 项目目标

一句话 + 角色 / 动作 / 数据。越具体，架构越准。

### 3. 技术栈（锁定）

写「**已锁定，不得替换**」。否则模型会偷偷把你选的 Svelte 换成 React。

### 4. 数据模型

```
### User
- 字段：id、email、passwordHash、nickname、role、createdAt
### Order
- 字段：id、buyerId、productId、amountCents、status、createdAt

要求：外键关系明确；常用查询字段加索引；软删除用 deletedAt；金额用整数分存储。
```

### 5. 接口契约

用表格给出方法 + 路径 + 用途：

```
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/v1/auth/register | 注册 |
| GET  | /api/v1/items | 分页列表（支持关键词/分类/排序） |
| POST | /api/v1/items | 新建（需登录） |
```

### 6. 页面与路由

列清单，并加一条通用要求：**每个页面都要有加载态、空状态、错误态、移动端单列布局**。

### 7. 设计规范（最容易被忽视、也最容易拉开差距）

**不要写**「界面要好看、现代、有设计感」——这是无效指令。

**要写**：

```
- 风格：极简 / 玻璃拟态 / 粗野主义 …
- 背景色：#FBFAF7；卡片面：#FFFFFF
- 文字：主 #1A1A1C，次级 #6B6B72；边框 #E7E4DC
- 强调色：#5B5BD6（主操作），#E8552F（关键状态）
- 字体：标题 Space Grotesk，正文 Manrope，代码 JetBrains Mono
- 圆角 10px；正文 16–17px、行高 1.6–1.7
- 颜色比例 70-20-10
- 禁止纯白/纯灰平铺背景，必须用渐变/纹理/光晕营造纵深
- 所有交互元素必须有 hover / active / focus-visible / disabled 四态
- 触摸目标 ≥ 44×44px；对比度 ≥ 4.5:1；尊重 prefers-reduced-motion
```

> 给出**色值、字号、圆角**这三个量级，产出质量会有肉眼可见的差别。

---

## 三、三条硬约束（强烈建议每次都写）

1. **禁止假数据写死的实现**，前端必须真实调后端，后端必须真实读写数据库
2. **统一响应格式与错误处理**，错误要有用户可读提示，且**表单校验失败要保留用户输入**
3. **输出完整文件路径 + 每个文件完整内容**，不要用「此处省略」占位

---

## 四、加上验收标准，让模型自检

在提示词末尾附一份勾选清单，并要求模型在最后逐条自检：

```
- [ ] 按 README 命令可一键启动，无缺失依赖
- [ ] 注册 → 登录 → 增删改查 → 刷新后数据仍在
- [ ] 未登录访问受保护接口返回 401，越权返回 403
- [ ] 表单校验失败时保留用户已填内容
- [ ] 移动端（375px）所有栅格塌缩为单列
- [ ] 仓库中无明文密钥
```

这一步能显著降低「看着完成了、实际跑不起来」的概率。

---

## 五、迭代，而不是一次成型

**错误做法**：一条提示词要求生成上万个文件、全部功能。

**正确做法**：

```
第 1 轮：只要求输出「文件树 + 数据模型 + 接口契约」，确认无误
第 2 轮：让它按契约逐个文件写实现（一次 3–5 个文件）
第 3 轮：运行、报错、把报错贴回去让它修
第 4 轮：按验收清单逐条过
```

一次性要求过长输出，后半段质量必然下降（上下文衰减）。

## 六、给不同编程工具的适配

| 工具 | 适配要点 |
|---|---|
| Cursor | 先让它建目录结构，再用 `@文件` 逐个补实现 |
| Claude Code | 提示词可直接喂，它能自己读写文件，注意分阶段确认 |
| v0 / 生成式 UI | 只给「设计规范 + 页面清单」，不要给后端内容 |
| 通用对话模型 | 必须自己贴回上下文，每轮带上前一轮的接口契约 |

---

## 七、自查：提示词写完检查这五条

- [ ] 有没有明确禁止假数据
- [ ] 技术栈是否写了「不得替换」
- [ ] 数据模型是否给了字段级清单
- [ ] 设计规范是否给了具体色值 / 字号 / 圆角
- [ ] 是否附了可勾选的验收标准
